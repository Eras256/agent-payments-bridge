# Real end-to-end run — 2026-09-14

What this is: a full run of `rafiki-local-playground-demo.cjs` against a
freshly built, freshly seeded instance of Rafiki's own [Local
Playground](https://github.com/interledger/rafiki/tree/main/localenv)
(Cloud Nine Wallet, `pnpm localenv:compose:psql`), run inside the
playground's own `rafiki_rafiki` Docker network. No part of the Open
Payments/GNAP flow below is mocked; the only thing scripted instead of
clicked is the consent screen (the mock IDP exposes plain HTTP endpoints
for exactly this — see the script's comments and
`localenv/mock-account-servicing-entity/app/lib/apiClient.ts` in the
Rafiki repo for the real client that normally calls them from a browser).

This is what `agent-payments-bridge`'s real code (`anchorPaymentCompletion`,
imported from this package's own `dist/src/index.js`, not a copy) is
exercised against in steps 10–11.

## How to reproduce

See the header comment in `rafiki-local-playground-demo.cjs`.

## What this proves, and what it doesn't

Proves: `agent-payments-bridge`'s completion-detection and anchoring logic
works against a real, live Open Payments/GNAP server — including the
harder case (outgoing payment, derived completion, no `completed` field)
— with real money moving between two accounts inside Rafiki's ledger
($6.10 debited from `bhamchest` including the seeded fee, $5.00 credited
to `gfranklin`).

Doesn't prove: behavior against the public shared test network
(`wallet.interledger-test.dev`) or against a production Rafiki deployment
— this run is entirely local, torn down after the run
(`pnpm localenv:compose:psql down`), and the account/key material above
(`private-key.pem`, `IDP_SECRET`) are the Rafiki project's own published
local-dev test fixtures, not secrets and not reachable outside a local
Docker network.
